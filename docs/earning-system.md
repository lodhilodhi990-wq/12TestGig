# Earning System

## Overview
The 12 Test Gig Earning System allows testers to earn rewards by completing testing activities. All financial transactions are stored using **integer minor units** (e.g., cents) to prevent floating-point inaccuracies.

## Reward Types
The system supports multiple configurable reward types per campaign:
- `campaign_completion`: Rewarded when all days/tasks of a campaign are completed.
- `daily_completion`: Rewarded upon successful validation of a full testing day.
- `task_completion`: Micro-rewards for individual tasks (if enabled).
- `bug_reward`: Rewarded for confirmed bug reports.
- `quality_bonus` & `on_time_bonus`: Additional discretionary campaign bonuses.

## Idempotency
Every reward generated by the system uses a unique deterministic idempotency key. For example:
- A Bug Reward uses the ID: `{bugId}_bug_reward`.
- A Daily Reward uses the ID: `{assignmentId}_{campaignDayId}_daily_completion`.

This guarantees that a duplicate network request or retry will never cause double-payouts.

## Campaign Budget Protection
Before generating any reward, the system runs a Firestore Transaction that verifies `amountMinor <= remainingBudgetMinor` on the Campaign. This guarantees that campaigns cannot be overspent, even under concurrent high load.
